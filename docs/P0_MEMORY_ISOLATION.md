# P0：人格记忆隔离止血说明

本补丁优先保证「不会串库」，因此采用 **fail closed**：系统无法明确解析当前人格／会话属于哪个记忆域时，会拒绝检索、写入和反思，不再自动回落到 `public`。

## 推荐配置

在 `conversation_scope_map` 中明确配置人格或会话。人格键优先于会话键：

```json
{
  "小白": "public",
  "小太": "xiaotai"
}
```

这样：

- 小白只读取及修改 `public`；
- 小太可以读取 `xiaotai` 与继承的 `public`；
- 小太只能修改 `xiaotai`，继承的 `public` 对小太是只读；
- `public` 永远不能读取 `xiaotai`。

如果现阶段确实需要让所有未配置会话进入公共域，必须显式加入保留键：

```json
{
  "小白": "public",
  "小太": "xiaotai",
  "__default__": "public"
}
```

建议先从日志确认 AstrBot 实际返回的人格标识，再决定是否设置 `__default__`。留空最安全。

`__quarantine__` 是系统保留隔离域，不能绑定给人格、会话或默认值。

## 历史数据处理

缺少 `memory_scope` 的历史向量记录无法可靠判断属于小白还是小太。本补丁将它们标为：

```text
__quarantine__
```

隔离记录不会被正常人格检索。后续必须通过专门审计／迁移工具人工归类，不能直接批量改成 `public`。

旧版 SimpleMemory 回灌仍按全库 `judgment` 去重，存在跨域覆盖风险。P0 期间该回灌入口已直接停用；下一阶段必须把去重键改为：

```text
(memory_scope, judgment)
```

在完成并验证该迁移前，不要手动调用旧回灌函数。

## 暂停的功能

旧版笔记文件表、切片 SQLite 和 Tantivy 索引没有 `memory_scope`。为了避免笔记内容进入错误人格或先被外部 rerank 服务看到，P0 期间暂时停用：

- `angel_note_create`；
- `angel_note_read`；
- `angel_recall` 中的笔记检索；
- DeepMind 自动笔记召回与注入。

普通长期记忆检索继续工作，而且 FTS／向量候选会在构建文档文本、交给 rerank 服务之前先按 scope 过滤。下一阶段需要为笔记文件、切片与搜索索引补齐 scope 后，才能重新启用笔记功能。

## 上线前

1. 完整备份中央 SQLite、向量索引、笔记目录和插件配置。
2. 检查 `conversation_scope_map` 是否同时覆盖小白和小太的实际人格标识。
3. 在测试会话分别创建一条带唯一标记的公共／私有记忆。
4. 验证小太可读取公共记忆，小白不能读取私有记忆。
5. 验证小太无法用公共记忆短 ID 执行 update／merge。
6. 查看迁移日志中的 `已隔离` 数量，并保留原始备份，暂不清理隔离记录。

## 回滚

代码可以回滚到补丁前提交，但不要把已标为 `__quarantine__` 的记录自动改回 `public`。数据回滚只能使用上线前完整备份。
